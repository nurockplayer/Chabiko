# Pronunciation audio

This replaces the undelivered 20-file Azure S0/Japan East package: browser speech makes pronunciation available immediately without waiting for a fixed asset delivery.

Pronunciation uses a layered source strategy: a committed static audio file is preferred when the manifest contains one; otherwise the browser generates speech with its installed Web Speech API voice. Static files are content-addressed and deterministic for a given generated response. Teacher recordings can replace a generated entry and take precedence. If neither source can play, the pronunciation control is unavailable and written learning remains complete.

Use `src/components/PronounceButton.astro` with `text` and `lang="zh-TW"` (Traditional/Taiwan) or `lang="zh-CN"` (Simplified/HSK). Add `slow` for a separate ゆっくり control. Mount the component once on a route to load its shared script and styles. For client-created controls, use the `pronunciation-button` class and the same `data-pronunciation-button`, `data-pronunciation-text`, and `data-pronunciation-lang` attributes; the shared runtime observes inserted controls and script changes. Call `playPronunciation` directly inside a user gesture, without waiting for voices to load.

The full manifest is never shipped to browsers. Playback uses `public/audio/index.json`, which maps each normalized `lang|text` key (for example `zh-tw|小姐，女士`) to its audio file. The pronunciation runtime fetches it once after the page's `load` event, so it never delays page content. Lookup in the click handler is synchronous; until the index arrives, or if the request fails, controls use browser speech exactly as when no static file exists. Player and generator share the text normalization in `src/lib/pronunciation/normalize.ts`, so index keys always match lookups.

Run `pnpm audio:generate --dry-run` to count distinct Chinese text and characters without credentials or network calls. Use a paid-tier (S0) Azure Speech resource: Microsoft's terms grant use rights for prebuilt neural-voice output to paid-tier customers, so free-tier (F0) output must not be committed. Set `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION`, confirm the tier, then run `pnpm audio:generate --confirm-paid-tier` to generate all missing audio; without the flag the generator refuses to write assets. `pnpm audio:generate --confirm-paid-tier --limit N` generates at most N pending entries. The generator uses `zh-TW-HsiaoChenNeural` for Traditional Chinese and `zh-CN-XiaoxiaoNeural` for Simplified Chinese, requests 24 kHz mono MP3, stores files under `public/audio/`, and updates `src/lib/pronunciation/manifest.json` together with the compact playback index `public/audio/index.json`. The provider interface is intentionally small so another cloud TTS provider can be added later.

To add a teacher recording, place the permitted recording under `public/audio/`, calculate its SHA-256 checksum, and add a manifest entry with `source: "teacher-recording"`, its text, language, root-relative file path (for example, `/audio/teacher-word.mp3`), checksum, an ISO `generatedAt` timestamp, and an identifying provider/voice description. Retain permission and attribution alongside the recording; adding a recording does not change the content review status. Keep the exact spoken text and language accurate. Then run `pnpm audio:generate --index-only` to rebuild `public/audio/index.json` from the manifest (no credentials or network needed); a test fails if the committed index and manifest disagree. Teacher entries take precedence over generated entries for the same normalized text and language. Do not claim teacher review unless a human has actually completed it.

Microsoft's [Azure Product Terms for Text-to-Speech](https://www.microsoft.com/licensing/terms/en-US/productoffering/MicrosoftAzure/allprograms) state that paid-tier customers may use prebuilt neural voice output in applications, including commercially. Confirm the terms that apply to the selected resource and use at generation time. Browser Web Speech is requested on the learner's device through its available voice service; Chabiko does not store or redistribute that output. Some device voices may require a network connection. No speech recognition, microphone capture, or pronunciation scoring is included.

Generated entries are recorded as synthetic and unreviewed (`source: "tts"`, `reviewStatus: "draft"`, `humanReview: false`). All audio is synthesized speech unless an entry's `source` is `teacher-recording`. Only a real reviewer record may mark a clip reviewed.

## Matched-text voice comparison (#526)

Under Node 24 with pnpm 12.11.2, run `pnpm audio:compare --gemini-voices 1` to preview the 14 verbatim items in `data/audio-eval/matched-text-v1.json` at normal and slow speeds. Omitting `--confirm-paid-tier` or passing `--dry-run` prints the selected voices, request counts, and estimates without calling synthesis or gcloud, regardless of credentials. The pinned source links identify existing Chabiko material, including drafts/pilots and a fixture. Focus notes are AI-provisional and await teacher review.

- **Azure HsiaoChen and HsiaoYu.** Set `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION` for a paid-tier resource. Estimated US$0.026940 for both voices at US$15/million billable characters, counting Han characters twice and including the slow prosody markup. See the [Microsoft output-use terms](https://www.microsoft.com/licensing/terms/en-US/productoffering/MicrosoftAzure/allprograms).
- **Google WaveNet A and B.** Set `GOOGLE_TTS_API_KEY` or use `GOOGLE_CLOUD_PROJECT` with an existing gcloud login (`gcloud auth print-access-token`). The API key takes precedence for WaveNet. Estimated US$0.002000 for both voices at US$4/million characters before any free allowance. See [Google Cloud pricing](https://cloud.google.com/text-to-speech/pricing).
- **Google Gemini-TTS Kore and Puck.** Set `GOOGLE_CLOUD_PROJECT` to a billing-enabled project with the Cloud Text-to-Speech API enabled and use an existing gcloud login. This uses the same Google OAuth path as WaveNet. The tool uses `gemini-2.5-flash-tts` with `cmn-tw` (Taiwan Mandarin, Preview). Each voice is estimated at US$0.019895 for 28 requests. Google charges US$0.50/million text input tokens and US$10/million audio output tokens (25 tokens/sec), with no free allowance. The estimate includes both the style prompt and the spoken text, using UTF-8 bytes to approximate input tokens and four characters/sec at normal pace or three at slow pace to estimate audio length. See the [Cloud Gemini-TTS guide](https://docs.cloud.google.com/text-to-speech/docs/gemini-tts), [REST authentication](https://docs.cloud.google.com/text-to-speech/docs/authentication), and [pricing](https://cloud.google.com/text-to-speech/pricing).

```sh
pnpm audio:compare --gemini-voices 1 --confirm-paid-tier
pnpm audio:compare --only google --gemini-voices 2 --confirm-paid-tier
```

The first example adds Kore to the four default voices (140 requests, estimated US$0.048835). The second compares both WaveNet voices with Kore and Puck (112 requests, estimated US$0.041790). `--only azure` and `--only google` select a base group. `--only gemini` selects Kore alone, and adding `--gemini-voices 2` brings in Puck. Missing credentials skip the affected provider. These private evaluation clips are synthetic and await teacher review. See the [Google Cloud terms](https://cloud.google.com/terms) and [TTS usage guidance](https://docs.cloud.google.com/text-to-speech/docs/basics).

The estimate budget defaults to US$0.05. `--max-usd` can lower it. A plan over the cap, such as all four default voices plus both Gemini voices, stops before synthesis. Up to two retries on HTTP 429/5xx are allowed when the cap covers the estimate for each attempt and all remaining first attempts. Gemini bills actual output duration, which can vary from the estimate. The Cloud TTS API exposes no output-token limit per synchronous request, so the local cap applies to estimated spend. Estimates exclude taxes and account-specific pricing or credits.

Output defaults to `~/Downloads/chabiko-voice-compare-<UTC-date>/`. Override with `--output /absolute/path/outside-the-worktree`. The tool refuses existing directories and worktree paths, including symlink aliases. A fresh random seed gives stable opaque clip filenames within each bundle and shuffles the candidate letters for each sentence. The private `key.json` records the seed and code/provider/voice/speed mappings, plus the Gemini model and prompt for each Gemini clip. Open `listening.html` offline or import it into an Artifact. It embeds all MP3s, offers normal/slow players and 1–5 ratings per sentence and voice, and reveals identities in the bottom disclosure. Ratings stay in the page without storage or network. Copy decisions before closing. The reveal key is visible in the HTML source.

No resume is attempted: a failure may leave partial clips and their key, without a listening page. Inspect partial output before choosing a fresh directory for another paid run; caps apply per invocation, not cumulatively across invocations. Keep all output outside the repo and do not publish it through the site's audio manifest.
