# Pronunciation audio

This replaces the undelivered 20-file Azure S0/Japan East package: browser speech makes pronunciation available immediately without waiting for a fixed asset delivery.

Pronunciation uses a layered source strategy: a committed static audio file is preferred when the manifest contains one; otherwise the browser generates speech with its installed Web Speech API voice. Static files are content-addressed and deterministic for a given generated response. Teacher recordings can replace a generated entry and take precedence. If neither source can play, the pronunciation control is unavailable and written learning remains complete.

Use `src/components/PronounceButton.astro` with `text` and `lang="zh-TW"` (Traditional/Taiwan) or `lang="zh-CN"` (Simplified/HSK). Add `slow` for a separate ゆっくり control. Mount the component once on a route to load its shared script and styles. For client-created controls, use the `pronunciation-button` class and the same `data-pronunciation-button`, `data-pronunciation-text`, and `data-pronunciation-lang` attributes; the shared runtime observes inserted controls and script changes. Call `playPronunciation` directly inside a user gesture, without waiting for voices to load.

Run `pnpm audio:generate --dry-run` to count distinct Chinese text and characters without credentials or network calls. Use a paid-tier (S0) Azure Speech resource: Microsoft's terms grant use rights for prebuilt neural-voice output to paid-tier customers, so free-tier (F0) output must not be committed. Set `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION`, confirm the tier, then run `pnpm audio:generate --confirm-paid-tier` to generate all missing audio; without the flag the generator refuses to write assets. `pnpm audio:generate --confirm-paid-tier --limit N` generates at most N pending entries. The generator uses `zh-TW-HsiaoChenNeural` for Traditional Chinese and `zh-CN-XiaoxiaoNeural` for Simplified Chinese, requests 24 kHz mono MP3, stores files under `public/audio/`, and updates `src/lib/pronunciation/manifest.json`. The provider interface is intentionally small so another cloud TTS provider can be added later.

To add a teacher recording, place the permitted recording under `public/audio/`, calculate its SHA-256 checksum, and add a manifest entry with `source: "teacher-recording"`, its text, language, root-relative file path (for example, `/audio/teacher-word.mp3`), checksum, an ISO `generatedAt` timestamp, and an identifying provider/voice description. Retain permission and attribution alongside the recording; adding a recording does not change the content review status. Keep the exact spoken text and language accurate. Teacher entries take precedence over generated entries for the same normalized text and language. Do not claim teacher review unless a human has actually completed it.

Microsoft's [Azure Product Terms for Text-to-Speech](https://www.microsoft.com/licensing/terms/en-US/productoffering/MicrosoftAzure/allprograms) state that paid-tier customers may use prebuilt neural voice output in applications, including commercially. Confirm the terms that apply to the selected resource and use at generation time. Browser Web Speech is requested on the learner's device through its available voice service; Chabiko does not store or redistribute that output. Some device voices may require a network connection. No speech recognition, microphone capture, or pronunciation scoring is included.

**Before the first full generation:** the manifest is currently bundled into the pronunciation client, which is fine while it is empty or small. A full run produces roughly 3,600 entries, so first switch playback to a compact, lazily fetched per-surface index (prefetched on page load, falling back to browser speech until it arrives) to keep mobile pages light.
