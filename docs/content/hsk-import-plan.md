# HSK Import Plan and Teacher Source Reconciliation

This issue-owned plan path now records the teacher-only outcome for Issue #81 and keeps the HSK source gate separate. Teacher workbook groups are the teacher's own curriculum difficulty and sequence, built through years of in-person teaching. They have no relationship to HSK levels. No teacher group, star, sheet, row, count, or record may be mapped to or used to infer HSK membership or level.

## Frozen Impact Map

- **Writers:** The unchanged `scripts/import-teacher-vocabulary-xlsx.py` CLI is the only generator for its manifest and source derivative. The committed `data/teacher-import/teacher-core-v1/source-profile.json` binds source/rights and reconciliation evidence. Tests create only their own temporary fixtures.
- **Consumers and validators:** The current importer validates each generated batch with `scripts/validate-content-schema.py`. Runtime consumers remain `src/content/loadTeacherVocabulary.ts` and `src/content/loadProductionLearnerCorpus.ts`, with the 20-row canonical batch at `data/vocabulary/teacher-core-v1/teacher-vocabulary-batch-01.json` and the 1,582-row canonical learner manifest at `data/teacher-vocabulary-preview/learner-manifest.json`. The authoring profile, manifest, and source derivative have no runtime consumer.
- **Legacy and compatibility:** Keep `teacher-core-v1`, `star-1` / `star-2`, existing IDs/order, the compatibility loader, corpus manifest, and all current HSK fixtures/loaders unchanged. Do not restore historical assumed-HSK labels/counts (including the old 568-row assumption) or old HSK loader/profile artifacts. Existing synthetic HSK pilot fixtures remain synthetic and separate.
- **Canonical workflow:** Run `uv run --locked python scripts/import-teacher-vocabulary-xlsx.py <workbook.xlsx> <new-empty-output-dir>`. Compare the full manifest and source batch byte-for-byte to the authoring evidence. The CLI accepts a missing or empty output directory and fails before mutation on a non-empty directory. It never deletes unrelated files.
- **Git/build/deployment/cleanup:** Commit only source profile, importer manifest, first-batch derivative, issue plan, and coupled regression/self-test changes. Do not commit the workbook, private local path, scratch outputs, or runtime imports. Do not change package/dependency/build/prune guards. Tests own and remove only their temporary directories; a dirty-output sentinel must survive a rejected CLI invocation.
- **Rights and provenance:** The workbook owner's attestation is [Issue #81 comment 5853229347](https://github.com/nurockplayer/Chabiko/issues/81#issuecomment-5853229347); it permits original teacher-authored workbook text for Chabiko product use, deterministic transformation, repository storage, publication, and distribution, with no additional attribution requirement and no broader relicensing grant. The semantic decision is [Issue #81 comment 5853390946](https://github.com/nurockplayer/Chabiko/issues/81#issuecomment-5853390946). Current production Japanese glosses retain their AI-provisional status; differences from the teacher-authored text are not human approval. Traditional forms/status remain as already committed.
- **Clean and dirty failures:** Pin source SHA, parser and lock evidence, and immutable real-source output digests in both the source profile and focused test. Compare every rejected reason/coordinate with the existing expansion plan, every accepted ID/order/coordinate with its existing batch and current production, and the complete accepted-plus-rejected coordinate set with the independent preview inventory. Fail tests on source/hash drift, any changed rejection, incomplete or duplicate row accounting, missing/extra accepted coordinates, batch/order/ID/source projection drift, forbidden HSK metadata, production contract drift, or change to the known Japanese-gloss differences. Missing source, malformed workbook, and non-empty output fail closed. Dirty developer files are preserved.

## Source and repeat evidence

The exact authoring-only input is `单词表(带图).xlsx` (144,849 bytes, SHA-256 `3fad65934dd3801fedfbd9e110f2c5bb8730b36d4117ee7a228cbf0089383f37`). The parser is the current #112 teacher importer, pinned in the source profile by its source hash and `uv.lock` hash. The observed source headers and required/ignored mappings are recorded in that profile.

Two fresh CLI runs from the exact workbook each produced 1,865 candidates, 20 accepted, 1,845 rejected, and one batch. Both complete manifests and batch files were byte-identical to each other and to the prior captured proof output. `manifest.json` preserves every rejection with its sheet, row, and reason; the current required-field and teacher difficulty-check rules were not weakened.

The accepted 20-row source derivative is an authoring record of workbook text. Its IDs, order, Simplified headwords, pinyin, difficulty/POS values, and source sheet/row coordinates match the current production first batch exactly. Eleven Japanese glosses differ. Preserve workbook Japanese in the authoring derivative and the current production glosses/provenance in runtime data. Existing production Traditional values/status are also untouched because this importer does not derive Traditional text. No candidate becomes newly human-reviewed or learner-eligible through this evidence.

The canonical 1,582-row learner corpus remains represented by `data/teacher-vocabulary-preview/learner-manifest.json`, loaded by `loadProductionLearnerCorpus()`. The existing `loadTeacherVocabulary()` adapter continues to read the already committed production batch and illustration data. The new authoring artifacts do not replace either loading boundary.
