# HearMandarin HSK source foundation

This authoring package admits only HearMandarin source IDs, Simplified Chinese, tone-marked pinyin, primary HSK 3.0 level, and observed global sequence for the 2,000 verified coordinates. The importer creates a complete disposition manifest and exactly the complete draft placements declared by the publication index. The current real declaration contains only `batch-001`, a 20-row AI-provisional Japanese draft batch. These authoring files are not connected to learner runtime data, and draft rows do not become human reviewed or runtime available through import.

## Canonical importer and publication declaration

The importer uses only the Python standard library and performs no network access. Run it with Python 3.14 or later, the exact pinned source JSON, and a new or empty output directory; the command interface remains unchanged:

```sh
python3 scripts/import-hearmandarin-hsk-json.py \
  --source /local/path/to/hsk-3-0-words.json \
  --output-dir /tmp/hearmandarin-hsk-import
```

Its `--self-test` option exercises the actual CLI in an isolated miniature repository. The real invocation reads the source profile, byte-pinned official verification receipt, publication index, the first Japanese companion, and one companion for each additional declared placement. It validates every input, source identity, retained-field projection, placement membership, join, and generated byte set before it publishes any output.

The current `publication-index.json` has exactly two keys: `publicationIndexVersion` and `placements`. Its version is the non-Boolean integer `1`. `placements` is a nonempty array of unique nonempty strings that begins with `batch-001` and is an ordered subset of complete groups in the immutable manifest plan. The initial real index declares only `batch-001`. Declarations cannot choose paths or rows, include unknown or blocked groups, reorder the plan, or omit the first placement. No future real placement or Japanese text is admitted by this publication.

The profile is version 2. Its immutable placement parameters keep the first batch at 20 eligible level-1 rows and later groups at a maximum of 50 rows, ordered by global sequence within each primary level. Placement IDs and filenames come from the immutable plan: the initial group is `batch-001`; subsequent per-level groups begin at `planned-level-L-batch-002`. Numbering is based on each level's planned chunks and is not renumbered when declarations select an ordered subset. For example, a level-2 placement `planned-level-2-batch-002` has companion `japanese/level-2-batch-002.json` and output `hsk-vocabulary-level-2-batch-002.json`. The level remains in the filename, so two levels can each have a batch `002` without colliding.

Each companion root has exactly `authoring` and `records`. `authoring` has exactly `method`, `status`, `reviewStatus`, `humanReview`, and `excludedSourceFieldsUsed`. The method is `Independently AI-authored from the supplied Simplified Chinese, tone-marked pinyin, and primary-level introduction context only.`; the remaining values are `ai-provisional`, `draft`, `false`, and `[]`. Each record has exactly `sourceId`, `globalSequence`, `simplified`, `pinyin`, and `japanese`. Its non-Boolean integer sequence and string source fields must match the complete ordered placement rows; Japanese text must be nonempty. The current `first-batch-japanese.json` remains byte-unchanged. A later separately admitted one-placement child must add an independently AI-authored provisional companion and its index declaration before running the same importer; this issue adds no real future companion.

The version-2 manifest is generated from the output bytes. `publication.batches` is an ordered list of `{placement, file, records, primaryLevel, sha256}` entries. `repositoryPublishedBatchCount` and `repositoryPublishedRecordCount` are derived from those entries, while `sourceEligibleIsHumanReviewed` and `sourceEligibleIsRuntimeAvailable` remain `false`. Eligible manifest rows in declared placements use `repositoryPublication: draft-published-to-repository` and include `repositoryBatchFile`; undeclared eligible rows remain `planned-not-published` with no file reference; blocked rows remain `blocked` with no batch placement or file reference. The manifest keeps the full 2,000-coordinate accounting, opaque `hm-hsk3-<sourceId>` IDs, blocked reasons, supplementary labels, and source metadata.

For the current one-placement declaration, the output set is exactly `manifest.json` and `hsk-vocabulary-batch-001.json`. These two initial-only comparisons show the existing names:

```sh
  data/hsk-vocabulary/hsk-vocabulary-batch-001.json
```

For any later declaration admitted by its owning child, use the same command and compare the complete generated set against every `publication.batches[].file` entry and its exact owned repository path. Confirm the manifest count, each file's byte count and SHA-256, and that the declaration, manifest entries, generated files, and owned repository files agree. Then review and copy only `manifest.json` and the exact declared batch filenames to their owned paths. Do not invent paths, slice or reassign rows, infer source IDs, or add a second writer. The existing `pnpm validate:affected` selection runs the foundation contract suite and the ordinary content validators for these package and output paths; the suite also invokes the existing schema and script-status validators for every declared batch. The exact workflow document is mapped to the same foundation suite. No separate pipeline or bespoke rebuild command is introduced.

The importer verifies the pinned JSON SHA and metadata, receipt identity, all 2,000 unique source IDs and coordinates, primary-level counts, the complete eligible retained-field projection, blocked-reason accounting, duplicate groups, supplementary labels, and each declared companion membership before writing. It rejects malformed or duplicate-key JSON, unsupported index versions or fields, declaration/path collisions, source/receipt/projection drift, companion and batch join drift, symlinked output directories, non-directory output paths, missing output parents, and non-empty output directories without changing caller-owned files.

The output writer stages generated bytes privately and publishes each output with an exclusive no-overwrite link. A filesystem error can occur after the manifest and some batches have been linked; the command reports failure and may leave that partial fresh output directory. Private staging is removed, but there is no multi-file atomic transaction or destructive rollback promise. Preserve and inspect caller data and the partial output. Recover by rerunning into a new fresh directory, comparing the complete declared set, and reviewing before copying. Do not delete partial output or caller files as recovery.
