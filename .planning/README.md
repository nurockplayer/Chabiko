# Historical Planning Archive

> **Status: HISTORICAL / NON-AUTHORITATIVE FOR CURRENT EXECUTION.**
>
> The files under `.planning/` preserve Chabiko's original project bootstrap, requirements, roadmap, phase plans, and state snapshots. They intentionally describe earlier stages of the project and are not maintained as a live mirror of GitHub Issues or production state.

## How to use this directory

- Use `.planning/` for historical rationale, original v1 intent, and provenance.
- Do **not** infer current completion, blockers, stack status, production readiness, or next work from historical checklists or `.planning/STATE.md`.
- Do **not** update old phase checklists merely to make them resemble today's GitHub state. That would erase useful historical context and create another status ledger.
- A current GitHub issue may explicitly reference a planning requirement or phase context. In that bounded case, use the referenced material only to the extent the current issue keeps it active.

## Current execution authority

Follow the source-of-truth precedence in `../AGENTS.md` and the documentation map in `../docs/README.md`.

For current work, start with the live GitHub issue and the active canonical contracts it names. Use current merged code, schemas, validators, and tests as implementation reality where no higher-priority contract defines the behavior.

This directory must never be used to bypass current fail-closed gates for rights, content review, security, provenance, or learner-facing publication.
